# Jellyfin 影视库、观看状态与刮削目录删除设计

## 意图与范围

Media Forge 已生成 STRM，并把刮削结果放在 NAS 目录；Jellyfin 通过另一条挂载路径把这些影片展示在影视库中。用户需要在现有“刮削配置”页连接 Jellyfin、查看影视库目录并刷新受影响的库；在“影片列表”查看 `root` 用户的观看状态、筛选已观看影片并批量删除。首页统计留到后续。

当前刮削配置保存外部 STRM 服务、MetaTube、`scrape_root` 和内部 `media_root`；刮削扫描将 `scraping_folder` 记录为 Jellyfin 可见的 `/media/...` 路径。影片列表已有刮削状态筛选和三种删除模式，但删除云存储时不会删除 NAS 上的刮削文件夹。现有刮削任务调度提供每日或每周指定星期、指定时间的形式，后端使用 APScheduler。

## 已确定的行为

- Jellyfin 使用一个服务地址和 API Key，观看用户固定为 Jellyfin 的 `root`。配置展示密钥已设置状态，不回传明文。
- 从 Jellyfin 读取影视库名称、ID、配置目录与刷新状态；展示而不修改 Jellyfin 目录配置。
- 多个影视库共用同一组挂载映射。例如 Jellyfin `/media/愛那あい/CJOD-496-C/CJOD-496-C.strm` 对应 NAS `/vol1/1000/Media/嘿嘿/日本/愛那あい/CJOD-496-C/CJOD-496-C.strm`。现有 `media_root` 与 `scrape_root` 是映射根，配置页只读展示解析后的映射关系，不重新开放旧的 `media_root` 输入项。
- 按本次 STRM 路径所属的 Jellyfin 影视库刷新。匹配多个影视库时逐个触发，并报告各自结果。配置页的手动刷新扫描当前 `scrape_root` 中存在的 STRM，定位这些 STRM 涉及的全部影视库并逐个刷新；没有命中的库不刷新。提供自动刷新开关；自动刷新覆盖 STRM 生成完成、NAS 刮削文件夹删除这两类变化。默认关闭自动刷新，待用户启用。
- 从 Jellyfin 同步 `root` 用户的影片观看数据到 Media Forge，再用本地状态渲染和筛选。提供手动同步按钮以及在刮削配置页设置的定时同步：启用开关、每日或每周指定星期、`HH:mm` 时间，沿用现有爬虫定时任务交互。默认关闭定时同步。
- 影片列表显示“已观看”“未观看”“未看完”“未入 Jellyfin 库”四种业务状态。没有完成过成功同步时显示“未同步”，而不能把未知状态误判为“未入库”。同步失败时保留上次成功的快照和时间，并提示数据可能过期。
- “已观看”可筛选；沿用列表当前的多选和批量删除交互，不隐式删除筛选结果的所有分页。
- “仅删除云存储”“同步删除数据库和云存储”都会删除被选影片在 NAS 的整个 STRM 所在文件夹，包括其他文件和子目录。例如删 `/vol1/1000/Media/嘿嘿/日本/愛那あい/CJOD-496-C`，不删演员目录。仅删除数据库不碰 NAS 文件夹。
- “仅删除云存储”保留影片数据库记录，并按现有模式更新存储状态；“同步删除数据库和云存储”才删除数据库记录。

## 不在本次范围

- 首页观看统计、历史播放事件明细、用户切换和多用户汇总。
- 从 Media Forge 修改 Jellyfin 的观看进度、影视库目录或媒体条目。
- 任意 cron 表达式、多时点计划、修改现有 STRM 服务的生成机制。
- 一键删除全部“已观看”查询结果；本次保留现有跨页选择规则。

## 实现途径

### 方案 A：列表实时联查 Jellyfin

每次列表请求同时读取 Jellyfin 并按 STRM 路径匹配。省去本地状态存储，但网络耗时会拖慢列表，Jellyfin 不可用时筛选和批量删除难以保持稳定。

### 方案 B：同步快照到本地（已选）

后台分页读取 Jellyfin 影片及 `root` 的用户数据，以 Jellyfin 媒体路径与本地 `scraping_folder` 的精确归一化路径匹配，保存 Jellyfin 条目 ID、观看状态、进度及最近成功同步时间。列表查询、筛选与批量操作使用本地快照。手动和定时同步共用同一任务入口；失败不覆盖上次成功数据。新增或删除 STRM 后由下一次同步修正“未入库”状态，也允许手动立即同步。Jellyfin 服务地址、API Key 或路径映射改变时，旧快照立即失效，状态回到“未同步”，直到新配置完成一次成功同步。

此方案符合现有服务端分页筛选、批量删除和后台任务结构；代价是观看状态存在可见的同步延迟，因此界面显示同步时间。

## 后端设计

1. 在 `backend/app/modules/` 建 Jellyfin 集成边界，使用当前后端 HTTP 客户端调用 Jellyfin。配置复用刮削配置文件的保存、校验和密钥掩码形式；密钥只在后端请求头中使用，不进入 URL、日志或前端响应。连接测试校验服务可达、密钥有效、可读取影视库，并能定位 `root` 用户。
2. 读取 Jellyfin virtual folders 的 `Locations` 和 `ItemId`。采用完整路径段的前缀匹配，找出受 STRM 文件路径影响的所有库；同一个库只刷新一次。手动刷新枚举当前 `scrape_root` 中的 STRM 后按相同规则归属库。按库 ID 调用 Jellyfin 项目刷新接口，返回每个库“请求已接受/失败”的结果，不把请求已接受解释成扫描完成。若 STRM 服务只是接受异步生成请求，必须在观察到文件生成或现有刮削扫描确认变化后再触发自动刷新，不能紧跟该请求盲刷。
3. 同步任务分页获取 Jellyfin 电影路径与 `root` 的 `UserData`。`Played=true` 为已观看；未标记已观看而播放位置大于零为未看完；其余已匹配影片为未观看。只用精确路径及受控的文件夹路径变体匹配本地 `scraping_folder`，不单凭番号猜测；一个条目或本地影片出现歧义时记录并跳过，避免错配。成功完成全量读取后统一更新快照；确认无 Jellyfin 对应项的本地影片为“未入 Jellyfin 库”，有歧义的影片显示“未同步/匹配异常”并不能进入已观看筛选或批量清理候选。单次任务防重叠，记录执行状态、时间、条目数、匹配数和错误摘要。定时任务启停、重启恢复与现有 APScheduler 方式一致。
4. 扩展影片列表过滤、序列化和数据库迁移，使观看状态可在服务端过滤；同步时间和失败状态由独立同步状态接口展示。数据库中持久化 Jellyfin 条目 ID、观看状态与必要进度，避免列表请求直接联查 Jellyfin。
5. 扩展既有删除流程而不新增删除模式。先从影片 `scraping_folder` 用当前 `media_root` → `scrape_root` 映射解析本地目录，预检所有待删目录：须在真实 `scrape_root` 下、不能等于根目录、不能是符号链接、需与该影片 STRM 所在目录一致，且不得与其他选中或未选中影片形成不安全的父子覆盖。确认弹窗列出将删除的 NAS 文件夹及云存储文件夹数量。执行时先删除云存储和 NAS 目录；“数据库和云存储”在两处清理成功后才删除数据库记录，“仅云存储”保留数据库记录并重算状态。已不存在的目录单列为跳过，其他失败返回逐项结果并保留数据库记录以便重试。云存储与 NAS 不具备跨系统事务，部分成功需明确呈现和记录，重试应能处理先前已删除的路径。
6. 删除后更新剩余影片的刮削状态；自动刷新开关开启时，只刷新实际受影响的 Jellyfin 影视库。若 NAS 文件夹删除失败，不报告该库已成功清理。

## 前端设计

- 在现有 `ScrapingConfigPage` 增加 Jellyfin 区块：服务地址、密钥掩码与更新、连接测试、`root` 用户状态、影视库目录列表、只读映射、自动刷新开关、手动刷新、观看状态手动同步、定时同步配置、上次同步结果和时间。沿用当前 Ant Design 表单与提示方式。
- 在影片列表增加观看状态列和筛选；尚未同步、最近一次同步失败或配置改变导致快照失效时显示明确提示及最近成功同步时间。不用任意时间阈值判断“过期”。批量删除继续使用已有多选与三种模式，含云存储模式明确展示 NAS 文件夹删除范围。
- 所有新请求走 `frontend/src/api/`；刮削配置、电影筛选和路由结构的变更按现有测试及 `frontend/README.md` 约定更新。

## 验证重点

- 用模拟 Jellyfin API 验证密钥认证、virtual folder 目录和 ID、`root` 用户数据、分页、四种状态、重复/歧义路径、部分刷新失败与同步失败保留旧快照。
- 验证 `/media` 到 NAS 根目录的映射，多个影视库匹配、自动刷新时机与定时任务启停/重启恢复。
- 验证三种删除模式、刮削文件夹完整删除、符号链接与越界阻断、目录缺失及云存储/NAS 部分失败后的可重试结果。
- 运行相关后端 pytest、前端聚焦 Vitest 与 `pnpm build`；不改动当前工作区已有的刮削图片和任务测试未提交内容。
